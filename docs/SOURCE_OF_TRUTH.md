# Source of Truth — AfraKala Django ERP

این سند مرجع تصمیم‌های اصلی پروژه است. هر توسعه‌ی بعدی باید با این سند سازگار باشد.

## نام پروژه

AfraKala Django ERP

نام‌های قبلی/هم‌خانواده:

- دستیار هوشمند افراکالا
- دستیار جنگجو پایتون افراکالا
- Afra Smart Assistant
- مرکز فرمان هوشمند افراکالا

## واقعیت پروژه

این پروژه قرار نیست فقط یک ربات چت باشد. هدف، ساخت پلتفرم عملیاتی برای فروش B2B لوازم خانگی است.

تمرکز اصلی:

1. لیست قیمت هوشمند
2. مدیریت کالا و تأمین‌کننده
3. قیمت‌گذاری وابسته به نرخ ارز
4. داشبورد مدیریتی فارسی RTL
5. اتصال امن به ربات‌ها و کارخانه داده
6. فروش، مالی، تحلیل، CRM و دستیار تصمیم‌یار

## مرزهای سیستم

### این ریپو چیست؟

این ریپو وب‌اپ/بک‌اند اصلی ERP افراکالا است؛ جایی که داده‌های معتبر، منطق قیمت‌گذاری، کاربران، نقش‌ها، داشبورد و APIها نگهداری می‌شوند.

### این ریپو چیست نیست؟

این ریپو کارخانه ربات‌ها نیست. ربات‌ها، خزنده‌ها و پردازشگرهای داده باید در سرویس جدا یا ریپوی جدا باشند و از طریق API امن به این سیستم وصل شوند.

ریپوی `dollar-tehran-bot` قبلاً به‌عنوان Afra Automation Platform تعریف شده بود؛ یعنی لایه جمع‌آوری، پاک‌سازی، اعتبارسنجی، صف، لاگ، مانیتورینگ و تحویل داده از طریق API. آن سیستم CRM نهایی، داشبورد نهایی یا موتور تصمیم‌گیری اصلی نیست.

## اصل فنی مهم

داده‌ی تمیز و قابل اعتماد از خود AI مهم‌تر است. بدون داده‌ی درست از کالا، قیمت خرید، قیمت فروش، نرخ ارز، مشتری، سفارش و تسویه، هیچ دستیار هوشمندی ارزش عملیاتی جدی ندارد.

## اولویت MVP

MVP باید کوچک ولی واقعی باشد:

کالا → قیمت خرید → نرخ ارز → محاسبه قیمت فروش → خروجی لیست قیمت/PDF → لاگ تغییرات → داشبورد ساده مدیر

هر قابلیت خارج از این مسیر، فاز بعدی است مگر اینکه برای کارکرد همین مسیر ضروری باشد.

## خط قرمزها

- ERP خیالی همه‌کاره نسازیم.
- قبل از تمیز شدن دیتابیس، AI پیچیده اضافه نکنیم.
- ربات‌ها را داخل هسته ERP قاطی نکنیم.
- قیمت‌گذاری دستی بدون لاگ و تاریخچه نباید منبع حقیقت باشد.
- service role و کلیدهای حساس فقط server-side باشند.
