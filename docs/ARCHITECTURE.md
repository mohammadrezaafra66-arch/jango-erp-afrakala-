# Architecture — AfraKala Django ERP

## معماری کلان

سیستم به دو بخش اصلی تقسیم می‌شود:

1. ERP / Smart Assistant Core
2. Automation & Data Factory

این ریپو مربوط به بخش اول است.

## 1. ERP / Smart Assistant Core

مسئولیت‌ها:

- منبع حقیقت داده‌های عملیاتی
- مدیریت کاربران و نقش‌ها
- مدیریت کالا، برند، دسته‌بندی و تأمین‌کننده
- مدیریت قیمت خرید و قیمت فروش
- نگهداری تاریخچه قیمت و لاگ تغییرات
- محاسبه قیمت پیشنهادی
- داشبورد مدیریتی
- API مصرفی برای ربات‌ها و پنل‌ها
- تصمیم‌یار فروش و مدیریت

## 2. Automation & Data Factory

مسئولیت‌ها:

- استخراج داده از منابع بیرونی
- جمع‌آوری نرخ ارز و شاخص‌ها
- پاک‌سازی و نرمال‌سازی داده
- تشخیص عدد پرت
- محاسبه میانگین/median و score اعتماد
- پردازش صفی
- مانیتورینگ و لاگ عملیاتی
- ارسال داده تمیز به ERP از طریق API

این بخش باید از هسته ERP جدا بماند.

## اپ‌های پیشنهادی Django

- `core`: تنظیمات مشترک، base models، audit fields
- `accounts`: کاربران، نقش‌ها، دسترسی‌ها
- `catalog`: کالا، برند، دسته‌بندی، ویژگی‌ها
- `suppliers`: تأمین‌کنندگان و شرایط خرید
- `pricing`: نرخ ارز، قوانین قیمت‌گذاری، قیمت فروش، تاریخچه قیمت
- `sales`: مشتری، سفارش، پیش‌فاکتور، فروش
- `finance`: تسویه، پرداخت، حسابداری سبک اولیه
- `bots`: کلیدهای API و قرارداد اتصال ربات‌ها
- `analytics`: گزارش‌ها و شاخص‌ها

## جریان اصلی MVP

1. ثبت کالا و برند
2. ثبت قیمت خرید
3. ثبت/دریافت نرخ ارز
4. اعمال قانون قیمت‌گذاری
5. تولید قیمت فروش
6. ثبت تاریخچه تغییر قیمت
7. خروجی گرفتن لیست قیمت
8. نمایش در داشبورد مدیر

## اصل جداسازی

ربات‌ها نباید مستقیم جدول‌های داخلی ERP را دستکاری کنند. ارتباط باید از APIهای محدود، لاگ‌دار و دارای API key انجام شود.
